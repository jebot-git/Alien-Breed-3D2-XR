ALIEN BREED 3D II XR — ORIGINAL ENGINE AUDIT
2026-10-27

Decision
Build the XR product in native C++. There is no JVM, Java UI or Java runtime
in the product. The original Amiga source history is the active branch's base.
The literal translation is an offline reference for moving the original fixed-
point gameplay into C++, preserving big-endian layouts and 50 Hz PAL timing.
Do not use the independent Rebirth simulation for movement, combat, pickups,
secrets, AI, lifts, doors or campaign progression.

The abandoned Java GPU prototype is retained only on reference/java-host-audit
(commit e52ddd7); its tests are reference evidence, not native-port validation.
Native migration sources, host and validation live under native/. The migration
helper is optional; normal CMake builds use checked-in C++ and require no Java.

Why not compile the original C directly?
The C covers platform, preferences, PVS and integration. Core gameplay remains
680x0 assembly (player.s, newplayershoot.s, newaliencontrol.s, objectmove.s,
newanims.s). The original Makefile requires m68k-amigaos-gcc, vasm and Amiga NDK.
A native host would still need translation/recompilation and the platform shim.
The literal Java translation already supplies these, with big-endian memory and
680x0 arithmetic semantics, rather than executing an emulated Amiga CPU.

Unfinished host seam found and corrected
Hires.headless previously skipped loop_DrawPlayer1/2 entirely. Those routines
also call Newanims.objmoveanim and populate original aiming/visibility tables.
The XR host now keeps these calls and stops DrawDisplay only after transforms
and aiming-table preparation, before software pixel drawing. Original gameplay
advances one PAL tick per released barrier, independent of display refresh.
The original end-level music also participates in the barrier, with an exposed
presentation phase, rather than blocking the GPU host for seconds.

FileIo.unLHA was an unwired stub. It now uses the existing =SB= decoder, checks
source/output sizes, and copies the decoded bytes into the allocated game block.
This restores the source-tree packed level/music loading path.

Data warning
The maintained source media contains development maps. Its level A has only ten
zones, whereas retail A has 134. Tests and extracted game assets use the retail
preservation disks, not that development level.
